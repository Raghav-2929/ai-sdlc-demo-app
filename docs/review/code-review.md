## Notes for the author

- Leaving the controller role filter off Approve is safe as built. `SessionAuthMiddleware` requires a session on every `/api` path (case-insensitive). Username and role come only from `UserSession`. `ApprovalLimits.LimitFor` returns null for anything except exact `Manager`/`Director`, so the check fails closed. The remaining risk is the wiring: no automated test covers `ApprovalsController`/`Handle`. A change like `new Approver(session.Username, "Manager")`, or deleting the 403 catch (the UI shows `error` for any status), would pass all 45 unit tests and the e2e. One `WebApplicationFactory` test would close the risk research R11 accepts.
- Concurrency is declared out of scope, but this scenario belongs in the PR's known-limitations list. `Approve` checks and assigns on the shared `Invoice` outside the repository lock. Sequence: request 1 (demo.director) sees no first approval; demo.manager records a first approval; demo.director's second request approves; request 1 then resumes and writes `FirstApprovedBy = demo.director`. The result is an Approved invoice whose record shows the same person twice, which looks like an AL-4 breach in any audit. A per-invoice lock around check and assign fixes it.
- AGENTS.md:77 says the mutation score "never drops below" the baseline, but `stryker-config.json` has `"break": 0` and CI does not run Stryker, so the gate is manual only. Consider `"break": 65` (the current total is 74.63%).
- Questions for the product owner. Separation of duties is not in the spec: whoever creates an invoice may also approve it (a Manager can create and approve a 50,000.00 invoice, or create a 600,000.00 one and give its first approval). Is that intended? Also, when a Manager gave the first approval and retries, the same-person reason says "a different person must give the second approval", but only a Director can. Should it say "a different Director"?
- The working tree has an uncommitted change to `scripts/ai-log/export-transcript.mjs` and an untracked `docs/context-experiment.md`. They are not in this PR. I reviewed the committed version (`HEAD`). `dotnet test backend/InvoiceApp.sln`: 45 passed, 0 failed.
